# Rules

These apply to all work in this project. New rules get added to the end of this list.

1. **Never commit or push without asking first.** Matt always wants to see the diff of whatever we build.
2. **Explain everything in plain language (ELI5).** Make sure Matt understands the full context: what we are doing and why.
3. **Give file and line numbers for every code reference**, so the location is easy to open and view.
4. **Grill Matt until you are 95% certain of what Matt is looking for before making a change.** Keep asking questions until then. Do not fill gaps with assumptions.
5. **Keep app text short and plain.** Labels, hints, and messages should be human readable and to the point, with no jargon or extra words. Only add a hint or explanation when it is really needed; most things should be clear from the screen itself.
